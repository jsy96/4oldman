## 功能总览

### 顾客（老年人）
- 查看历史订单（含异常原因）、取消未开始的预约
- 预约下一次服务：选项目 → 选日期时间 → 备注
  - **冲突智能提醒**：若该时段与自己的服务员其他顾客的预约冲突（含前后 30 分钟路程缓冲），弹窗提醒并列出冲突单、推荐当天最近的空闲时段，可一键改约或坚持原时间下单
- 账户余额与每一笔明细（充值/扣款/退款，每笔显示余额变化）；余额可为负（欠费提示）
- 「我的」页显示专属服务员姓名电话，一键拨号/发短信
- 大字号适老化界面

### 服务员
- 工作台：今日订单数 / 明日待确认数 / 本月完成数 / 本月酬金
- **前一天确认**：明日待确认订单逐单或一键全部确认
- 完成服务（自动从顾客账户扣款并记账）、上报异常（顾客不在家/临时取消/身体原因等 6 类）
- 订单查询：**今天（默认）/ 明天 / 后天 / 未来 / 历史订单**；每单显示顾客姓名、地址、预约时间
- **AI 行程路线**（按日期）：按预约时间排程，地图显示驻地（🏠）和编号站点（1、2、3…）+虚线路径，**每段标注预计骑行时间与两单预留间隔**；结合 Open-Meteo 天气预报——雨/雪自动降速并提醒带雨具；自动避开 11:30-12:30 午餐时段；按当日气温预估电瓶车电量消耗（48V20Ah 电池模型，低温加大耗电）并给出补电建议
- **一键检查时间安排**：逐段判断「两单间隔 ≥ 骑行时间 + 准备时间（10分钟）」，输出 合理 / 偏紧 / 会迟到；距离按高德骑行路网实测（无 Key 时直线估算）
- 每个订单/顾客卡片上有 📞 拨号 / 💬 短信 按钮（手机浏览器直接拉起拨号盘和短信）

### 管理员
- 人员管理：服务员和顾客的增删改（软删除=停用，保留历史数据）；顾客指派固定服务员（一对多）；**地图选点**设置居住位置（用于路线规划）；重置密码
- 服务项目管理：名称/时长/价格/服务员酬金，停用下架
- 订单管理：多维筛选查询；**代顾客下单**（电话预约场景）；改期、改派其他服务员、标记完成、**取消并自动退款**、恢复确认；每单完整操作日志可追溯
- 异常订单处理：见下方流程
- 统计：按时间范围 × 服务员 × 顾客 × 服务项目交叉筛选；订单量/完成/异常/取消、服务收入、退款、酬金、未发酬金；按服务员/项目/月份分组表；一键导出 CSV（Excel 可直接打开）
- **行程检查（地图页）**：按日期逐个服务员检查时间安排合理性，同一算法；点「查看地图」查看该员工当天路线，每段标注骑行预估时间与两单间隔
- 批量充值：按月给勾选的顾客每人充固定金额（虚拟币），全部入账并留痕
- 酬金发放：选服务员+时间区间 → 预览已完成未发订单明细与合计 → 确认发放；已发放不可重复发放，保留发放历史

### 异常订单处理流程
1. **发现**：服务员上门遇顾客不在家/临时取消等 → 在订单上「上报异常」（选类型+说明）→ 订单转「异常」状态
2. **处理**（管理员在 订单管理 → 筛选「异常」）：
   - **改期**：调整预约时间，订单自动恢复「已确认」（若新时段有冲突会提示）
   - **改派**：转给其他服务员
   - **标记完成**：部分完成等场景按正常价完成并扣款
   - **取消退款**：已扣款的自动原路退回顾客账户，生成退款流水
   - **恢复确认**：联系上顾客后恢复原时间上门
3. **追溯**：以上所有动作均写入订单日志，随时查看

## 计费模型

- **服务金额 = 项目单价（元/小时）× 实际服务时长**。下单时自选时长（默认取项目的默认时长），单价与酬金由管理员在服务项目中维护
- **下单前校验余额**：顾客自约与管理员代下单都会检查顾客余额，余额不足直接拒绝（提示所需金额与当前余额）；需先由管理员充值
- 顾客余额为虚拟币（内部以「分」存储）。完成订单时按订单快照金额扣款；取消未完成订单自动退款（如已扣款）
- 服务员酬金按「项目默认时长酬金」随实际时长等比换算，下单时快照到订单；管理员按时间区间对「已完成且未发放」订单批量发放
- **时间冲突规则**：同一服务员前后两单必须间隔 ≥30 分钟（含路途缓冲），顾客端冲突订单无法提交；管理员代下单冲突时需二次确认强制下单

## 技术栈

- 后端：Python 3.12 + Flask 3 + SQLite（WAL），无外部数据库
- 前端：原生 HTML/JS/CSS（无构建步骤）+ Leaflet 1.9.4（已本地化，无需 CDN）
- 天气：Open-Meteo 免费预报 API（无需 API Key，需外网；离线时路线仍可规划，仅天气显示不可用）
- 地图底图：默认高德瓦片（中国城市），可在 `config.json` 切换 `osm`（海外）

## 部署说明（Vercel / Cloudflare 适配性）

**结论：本应用不能直接部署到 Vercel 或 Cloudflare。** 原因：

- 应用是 **Flask 常驻服务 + SQLite 本地文件**，所有订单/账户数据写在本机 `data/care.db`
- Vercel 的 Python Serverless 函数**文件系统不持久**（每次调用即弃、可能多实例），SQLite 数据会丢失且互相不一致
- Cloudflare Workers/Pages **不支持 Flask 常驻 Python 应用**（Pages 仅静态资源）

**可行的公网部署方案（按省事程度排序）：**

| 方案 | 改动量 | 说明 |
|------|--------|------|
| 局域网直连（现状） | 无 | 手机连同一 WiFi 访问 `http://电脑IP:8000`，最简单 |
| 内网穿透 | 无 | 本机跑 cpolar / frp / 花生壳，把 8000 端口映射出去；注意设强密码 |
| VPS 部署 | 无 | 任意云服务器（宝塔/1panel）装 uv 后直接 `python server.py`，配 Nginx + HTTPS |
| Fly.io / Railway / Render | 极小 | 免费容器平台，挂持久卷（volume）即可保住 SQLite，代码不用改 |
| 强行上 Vercel/CF | 大 | 需换云数据库并重写数据层，前端静态部分可放 CF Pages——不推荐 |

**云数据库选型（国内访问优先）**：本应用数据量小（单店日均几十单）。**腾讯云内用户推荐：云函数 SCF + 腾讯云 MySQL（同区内网）**，延迟 <3ms；本地/轻量服务器用户直接用 SQLite 零改造。海外免费库（Neon/Supabase）国内访问延迟 150-300ms，不推荐生产使用（代码已兼容，连接串填 `postgresql://…` 并自行安装 psycopg2-binary 即可）。

### 云开发环境「云托管」部署（MySQL 在云开发环境内时用这个）

连接串是内网 IP（如 `172.17.0.6`）说明 MySQL 在云开发环境内部，**只有同环境的服务能连**，独立云函数 SCF 连不上 → 用环境内「云托管」：

1. `secrets.json` 填好 `database_url`（账号密码来自环境控制台的数据库页面，密码忘了可在该页重置）与 `amap_key`
2. `.venv/Scripts/python.exe pack_run.py` → 生成 `cloudbase_run.zip`（含 Dockerfile，依赖云端构建；账号还是占位符会拒绝打包）
3. 控制台 → 云开发 → 你的环境 → **云托管** → 新建服务（如 `eldercare`，0.25核/512MB 起步）→ 代码「本地上传」选 zip → **监听端口 8000**
4. 部署完成后「访问地址」即默认 HTTPS 域名，手机直接用（首次冷启动稍慢，之后毫秒级）
5. 若访问数据库超时：服务设置 → 网络开启内网访问/与环境同 VPC
6. 首次访问自动建表+演示数据，登录后立即改密码

后续改代码：重跑第 2 步 → 服务页面「重新部署」上传新 zip 即可。

### 腾讯云函数 SCF 部署（MySQL 是独立云数据库 CDB 时用这个）

**方式一：一键部署（推荐，2 条命令）**

```bash
# 1. 打包（生成 scf_bundle.zip）
.venv/Scripts/python.exe pack_scf.py
# 2. 部署（创建/更新函数+环境变量+VPC+触发器）
.venv/Scripts/python.exe deploy_scf.py --region ap-guangzhou --vpc-id vpc-xxx --subnet-id subnet-xxx
```

前提：`secrets.json` 已填 `tencent_secret_id` / `tencent_secret_key`（控制台 → 右上角头像 → 访问管理 → API 密钥管理 → 新建密钥，只放本文件不入 git）、`database_url`、`amap_key`。函数已存在时自动改为更新模式；触发器自动创建失败时会提示控制台手动路径。

**方式二：控制台手点（6 步）**

1. **建库**：控制台 → 云数据库 MySQL（基础版即可，与函数同地域如广州/上海）→ 初始化账号和库（如 `oldcare`）。内网地址形如 `10.0.x.x:3306`
2. **打包**：本机执行 `.venv\Scripts\python.exe pack_scf.py` → 生成 `scf_bundle.zip`（含 Linux x86_64 依赖，按 Python 3.9 打包，**函数运行时要选 Python 3.9**）
3. **建函数**：控制台 → 云函数 SCF → 新建 → **Web 函数** → 代码本地上传 zip → 启动命令 `python server.py`
4. **网络**：函数「高级配置 → 网络」勾选**与 MySQL 同一 VPC 和子网**（内网互通，无需公网）
5. **环境变量**（函数配置 → 环境变量，优先级高于 secrets.json）：
   - `DATABASE_URL` = `mysql://账号:密码@10.0.x.x:3306/oldcare`（密码含特殊字符需 URL 编码）
   - `AMAP_KEY` = 高德 Key（可选）
6. **访问**：函数「触发管理 → API 网关触发器」得到默认 URL（无需备案域名；自定义域名需备案）。首次冷启动约 2-5 秒，之后毫秒级

> 说明：本应用是 SQL 数据库，**首次访问自动建表并写入演示数据，无需手动建表，也不使用云开发的文档「集合」**。MySQL 实例购买需在控制台完成（涉及付费，不建议脚本代建）。上线后登录改掉所有演示账号密码。

SCF 计费参考：免费额度（云函数每月 100 万次调用 + 40000 GBs 资源）对单店使用量绰绰有余；MySQL 基础型约 30-80 元/月，是本方案主要成本。

公网部署安全清单：① 全员改强密码；② API 网关已默认 HTTPS（拨号/短信链接可用）；③ 不要把管理端地址公开传播；④ 密钥一律走环境变量或 `secrets.json`，绝不入 git。
